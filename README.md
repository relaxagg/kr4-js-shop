# TechPoint · kr4-js-shop · Контрольная работа №4

**Тема** — JavaScript: интерактивность, DOM, события, формы и валидация.
**Дисциплина** — фронтенд и бэкенд разработка.
**Автор** — Юрченко Георгий Владиславович, группа ЭФБО-04-25.

Проект создан на основе **КР №3 `kr3-responsive-shop`** (адаптивный HTML/CSS-магазин техники TechPoint), который, в свою очередь, продолжает КР №1. Вёрстка и адаптивность сохранены, а вся интерактивность КР №4 написана на чистом JavaScript без библиотек.

## Запуск

Откройте `index.html` в браузере — проект работает и без сервера (скрипты подключены обычными тегами с `defer`, без ES-модулей). Для проверки через локальный HTTP-сервер выполните в корне проекта:

```bash
python3 -m http.server 8000
```

и откройте `http://localhost:8000/`.

Опубликованная версия (GitHub Pages): будет добавлена после публикации репозитория.

## JavaScript-файлы

- `data.js` — массив `products` из 10 товаров, объект категорий `CATEGORIES`, функции `getProductById`, `formatPrice`, `pluralize`.
- `catalog.js` — `createProductCard` (генерация карточки через `createElement`/`textContent`/`classList`/`append`), `initCatalog` (поиск, фильтр, сортировка, счётчик, пустое состояние), `renderPopularProducts` (главная), `renderProductPage` (страница товара), `attachCardHandlers` (делегирование кликов по кнопкам карточек).
- `cart.js` — состояние корзины и избранного в `localStorage`, функции `addToCart`, `setCartQuantity`, `removeFromCart`, `clearCart`, расчёт суммы `calculateCartTotals` через `reduce`, промокоды, отрисовка страницы корзины `renderCartPage`.
- `modal.js` — открытие/закрытие модального окна заявки, подстановка названия товара, закрытие по Escape и клику по фону.
- `validation.js` — правила проверки полей (`VALIDATORS`), вывод ошибок рядом с полями, общая логика `initValidatedForm` с имитацией отправки, инициализация формы заявки и формы обратной связи.
- `main.js` — мобильное меню, тёмная тема, счётчик корзины в шапке, всплывающие сообщения `showStatusMessage` (вместо `alert()`), запуск всех модулей. Каждый блок проверяет наличие элементов, поэтому на любой странице консоль чистая.

Скрипты подключены в порядке `data.js → cart.js → catalog.js → validation.js → modal.js → main.js`; `main.js` запускает инициализацию после загрузки остальных файлов.

## Массив товаров

В `js/data.js` — 10 товаров с единой структурой:

| Поле | Смысл |
| --- | --- |
| `id` | уникальный числовой идентификатор |
| `title` | название (по нему работает поиск) |
| `category` | ключ категории: `phones`, `headphones`, `accessories` |
| `price` | цена **числом**, в рублях |
| `isAvailable` | наличие (`true`/`false`) |
| `oldPrice`, `badge`, `rating`, `brand`, `description`, `image`, `imageAlt`, `features`, `specs` | дополнительные поля для бейджей, старой цены, рейтинга, карточки и страницы товара |

Категории в фильтре каталога строятся из того же объекта `CATEGORIES`, поэтому значения всегда совпадают. Один товар (`Redmi Note 13 Pro 6/128`) специально сделан отсутствующим (`isAvailable: false`), чтобы показать состояние «Нет в наличии». Разные объёмы памяти одной модели используют одно фото — это учебный проект.

## Реализованные функции базовой части

- **Генерация карточек.** Все карточки в каталоге и на главной создаются через `document.createElement`, текстовые данные выводятся через `textContent`, классы добавляются через `classList`, элементы собираются через `append`. Вручную карточки в HTML не написаны.
- **Поиск.** Поле «Поиск по названию» реагирует на событие `input`: список обновляется на каждый символ, сравнение без учёта регистра (`title.toLowerCase().includes(query)`).
- **Фильтрация.** Выпадающий список категорий реагирует на `change`. Дополнительно работают фильтры «Только в наличии» и «Только избранное».
- **Сортировка.** По цене (возрастание/убывание), по названию (`localeCompare`) и по рейтингу. Сортировка применяется к копии массива (`[...filtered].sort(...)`), исходный порядок данных не меняется.
- **Счётчик и пустое состояние.** Над списком выводится «Найдено: N товаров» с правильным склонением. Если ничего не найдено, показывается оформленный блок с текстом запроса, кнопкой «Сбросить фильтры» и ссылкой на заявку.
- **Валидация формы заявки** (`order.html`): пустая форма не проходит; имя — от 2 символов, только буквы/пробелы/дефис; e-mail — по регулярному выражению; телефон — 10–11 цифр, начиная с 7/8 (формат `+7 (900) 000-00-00`); товар — выбран из списка; согласие — отмечено. Ошибки выводятся рядом с полями и в общем блоке, не через `alert()`. После корректного заполнения появляется сообщение об успешной подготовке заявки.
- **События.** Все обработчики подключены через `addEventListener()` (`click`, `input`, `change`, `submit`, `reset`, `keydown`), inline-обработчиков в HTML нет. Для динамических карточек и строк корзины используется делегирование событий.
- **Безопасный вывод.** `innerHTML` не используется нигде: пользовательские данные, данные товаров и `localStorage` выводятся только через `textContent` и свойства элементов (`src`, `href`, `value`).

## Самостоятельные доработки

1. **Корзина** (`cart.html`, `cart.js`). Добавление из каталога и со страницы товара, изменение количества кнопками «−»/«+», удаление позиции, полная очистка. Корзина хранится в `localStorage` (ключ `techpoint-cart`) и переживает перезагрузку.
2. **Расчёт суммы через `reduce`.** `calculateCartTotals` считает сумму позиций `items.reduce((sum, item) => sum + price * quantity, 0)`, отдельно выводит скидку и итог «К оплате».
3. **Промокоды.** `TECH10` — скидка 10%, `STUDENT15` — скидка 15%. Промокод сохраняется в `localStorage`, сумма пересчитывается сразу; пустой код сбрасывает скидку. Неверный код даёт понятную ошибку на странице.
4. **Избранное.** Кнопка-сердечко на каждой карточке и на странице товара (`aria-pressed`), сохранение в `localStorage` (`techpoint-favorites`), фильтр каталога «Только избранное».
5. **Тёмная тема.** Кнопка 🌙/☀️ в шапке переключает класс `theme--dark` у `body`, который меняет CSS-переменные. Выбор сохраняется в `localStorage` (`techpoint-theme`) и применяется на всех страницах.
6. **Счётчик товаров в шапке.** Бейдж у ссылки «Корзина» показывает общее количество товаров и обновляется через собственное событие `cart:changed` на любой странице.
7. **Улучшенные карточки.** Рейтинг, бейджи («Скидка», «Хит», «Новинка»), старая цена, состояние наличия; у отсутствующего товара кнопка покупки заблокирована, фото приглушено.
8. **Динамическая страница товара.** `product.html?id=N` строит галерею, описание, характеристики и кнопки из массива данных; при неверном id показывает оформленное состояние «Товар не найден».
9. **Имитация отправки формы.** Кнопка блокируется и показывает «Отправка…», через 900 мс появляется сообщение об успехе с названием товара, форма очищается. Работает в форме заявки, модальном окне и форме обратной связи.
10. **Расширенная валидация.** Помимо базовых проверок: имя только буквами, сообщение от 10 символов, ошибка исчезает при исправлении поля, поля получают `aria-invalid` и связанный `aria-describedby`, фокус переводится на первое некорректное поле.
11. **Расширенное пустое состояние каталога.** Иконка, текст с текущим запросом, подсказка, кнопка сброса фильтров и ссылка «Оставить заявку»; аналогичные состояния у корзины и страницы товара.
12. **Модальное окно заявки.** Нативный `<dialog>` на главной: открывается кнопкой «Заказать» на популярной карточке, название товара подставляется через `textContent`, закрывается кнопкой, Escape и кликом по фону.

## Как проверить (сценарии для защиты)

1. Открыть `catalog.html` — 10 карточек сгенерированы JS, счётчик «Найдено: 10 товаров».
2. Ввести `galaxy` — список обновляется на каждый символ.
3. Выбрать категорию «Наушники» — остаётся один товар.
4. Сортировка «Сначала дешевле» — первый товар за 2 490 ₽; «По названию (А–Я)」 — порядок по алфавиту.
5. Ввести `абракадабра` — пустое состояние с запросом и кнопкой сброса; сброс возвращает все товары.
6. Нажать «В корзину» у двух товаров — счётчик в шапке растёт; открыть `cart.html`, поменять количество, применить `TECH10` — сумма пересчиталась; перезагрузить страницу — корзина и промокод сохранились.
7. Открыть `order.html`, отправить пустую форму — ошибки у полей; заполнить некорректный e-mail/телефон — ошибки; заполнить корректно — «Отправка…», затем сообщение об успехе и очистка формы.
8. Переключить тёмную тему, перейти на другую страницу — тема сохранилась.
9. Добавить товар в избранное, включить фильтр «Только избранное» — виден только он.
10. DevTools → Console на всех шести страницах — ошибок нет.
